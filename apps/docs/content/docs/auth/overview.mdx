# Authentication methods

Pick methods by how your agents arrive. You can enable several at once — the middleware tries
them strongest first and the first that verifies wins.

## Server methods — `@agentronics/sdk/server`

Verified from the HTTP request, so they work for agents that never run your JavaScript.

| Method | Best for | Agent sends | Plan |
|---|---|---|---|
| [Web Bot Auth](/docs/auth/web-bot-auth) | Signed agents (e.g. OpenAI's ChatGPT agent) | RFC 9421 signature headers | All plans |
| [Agent API keys](/docs/auth/api-keys) | Agents you or your customers run | `Authorization: Bearer agk_…` | All plans |
| [Verified crawlers](/docs/auth/verified-crawlers) | Search and AI crawlers | Its user agent (checked by reverse DNS) | All plans |
| [OAuth2](/docs/auth/oauth2) | Agents with an identity provider | A client-credentials access token | Pro+ |

## Enterprise identity

For agents that already carry workload or enterprise identity. Verified by the Agentronics
gateway.

| Method | Best for | Plan |
|---|---|---|
| [SSO / OIDC](/docs/auth/sso) | Agents signing in through your IdP | Business+ |
| [SPIFFE](/docs/auth/spiffe) | Workload identity (JWT-SVIDs) | Business+ |
| [mTLS](/docs/auth/mtls) | Client-certificate agents behind your proxy | Business+ |
| [Google agents](/docs/auth/google-agent) | Google-issued agent identities (SPIFFE) | Business+ |

## Browser methods — `@agentronics/sdk`

For WebMCP clients and agents operating your page. See [Browser agents](/docs/auth/browser-agents).

| Method | What it proves | Trust |
|---|---|---|
| Detection | An agent is present (WebMCP, DOM driver) | `detected` |
| Self-declaration / `X-Agent` header | The agent says who it is | `declared` |
| Extension token, bearer token | A token your backend verifies | `verified` |
| Session link | The agent acts for a signed-in user | `linked` |

## Choosing

- **Start with Web Bot Auth + verified crawlers.** They're on by default and need no work from
  agent operators.
- **Add API keys** for agents you issue credentials to.
- **Add OAuth2 or enterprise identity** when agents come from an organisation that already has
  an identity provider.
- Keep unverified agents **allowed** until the logs show your real traffic, then
  [block them](/docs/access-rules).
