# Stream auth events to the console

Every agent authentication becomes an [auth log](/docs/auth-logs) entry. Stream them to the
Agentronics console and they fill the **Agents**, **Logs** and **Sessions** views and your
[monthly active agent](/docs/concepts/monthly-active-agents) count.

Events flow **from your server to ours**:

```
your middleware ──toTraceEvent()──► exporter ──Bearer agtx_ik_…──► POST /v1/sdk/events ──► console
```

## 1. Create an ingest key

In the console, open **Settings → Ingest keys → Create key** and copy the `agtx_ik_…` value —
it's shown once. The page also shows your **ingest URL**.

<Callout type="warn">
  The ingest key is a **secret**. Keep it on your server; never ship it to the browser.
</Callout>

## 2. Export from the middleware

```ts
// middleware.ts
import { agentronicsMiddleware } from '@agentronics/sdk/next'
import { toTraceEvent } from '@agentronics/sdk/server'
import { createDashboardExporter } from '@agentronics/sdk'

const exporter = createDashboardExporter({
  url: process.env.AGENTRONICS_INGEST_URL!,   // from Settings → Ingest keys
  ingestKey: process.env.AGENTRONICS_INGEST_KEY!,
})

export default agentronicsMiddleware({
  onResult: ({ result, decision, request }) => {
    const event = toTraceEvent(result, decision, { siteId: 'shop-acme', request })
    if (event) void exporter.export([event]).catch(() => {}) // never block the request
  },
})
```

Each agent request sends one small batch. At high agent volume, collect events and export up
to 100 per call instead.

## 3. Or post events from any backend

No SDK needed — `POST` a batch of events:

```bash
curl -X POST "$AGENTRONICS_INGEST_URL/v1/sdk/events" \
  -H "authorization: Bearer $AGENTRONICS_INGEST_KEY" \
  -H "content-type: application/json" \
  -d '{
    "events": [{
      "id": "evt_01J9…",
      "siteId": "shop-acme",
      "sessionId": "https://chatgpt.com",
      "occurredAt": "2026-10-01T12:00:00Z",
      "type": "auth.identity_presented",
      "outcome": "success",
      "agent": { "class": "crawler", "trust": "verified", "vendor": "OpenAI" },
      "metadata": { "protocol": "web-bot-auth", "subject": "https://chatgpt.com", "page": "/products" }
    }]
  }'
```

Ingest is idempotent on the event `id`, so retries are safe. The response is
`{ ok, accepted, deduped }`. Batches hold 1–100 events.

## Troubleshooting

| Response | Cause |
|---|---|
| `401 invalid_ingest_key` | Wrong or revoked key — create a new one in Settings. |
| `403 ingest_key_write_only` | Ingest keys can only `POST` events; they can't read data. |
| `400 validation_failed` | The body doesn't match the event schema; `detail` lists the fields. |
